# 内容库近重复检测

我们做内容库的去重。库里几百万篇东西，转载和轻微改写的特别多，完全按文本相等去重只能抓到一小部分；之前试过两两比相似度，跑了两天没跑完就放弃了。想自己写一个近重复检测的库。

判定的口径是按相似度阈值来的，阈值可配置。要求是召回和误报都要达标：samples 里那份带标注的数据集上，该抓出来的不能漏、不该抓的不能抓进来，门槛写在下面，差一点都算不过。内存是硬约束：几百万篇的规模，不许把所有文档的完整特征全堆在内存里，必须想办法分块处理，跑完的内存峰值要看得出来是可控的。结果要确定：同一份数据跑两遍，分组和组内顺序必须一样；每组用哪篇当代表也要有明确规则。边界情况要想到：空文档、只有几个字的、完全一样的，还有看起来像但其实无关的。量上，samples 里那份数据集要在几分钟内跑完。实现只用标准库，测试用 unittest。

仓库里只有这份说明和 samples 里的样例数据集与期望分组，代码从零写。

## 判定口径

1. **归一化**：去掉所有空白字符（空格、制表、换行等），ASCII 字母转小写，其余字符原样保留（**标点保留**，改动标点算改动）。
2. **特征**：归一化后取字符级 **3-gram**——从左到右滑动、每次取 3 个连续字符，重复的只算一次，得到一个集合。归一化后长度小于 3 时，整串就是唯一的特征；长度是 0（空文档）时特征集是**空集**。
3. **相似度**：Jaccard 系数 `|A ∩ B| / |A ∪ B|`。两个空集之间的相似度定义为 `1`（两篇空文档算完全一样）。
4. **判定**：相似度 `≥ 阈值 τ` 视为近重复；`τ` 默认 `0.8`，可配置。样例的期望分组就是按 `τ = 0.8` 算出来的。
5. **分组**：把「相似度 ≥ τ」当成一条边，最终的组是图的**连通分量**（传递闭包）。所以 A 与 B 相似、B 与 C 相似时，三者会在同一组，即使 A 与 C 的直接相似度没到阈值。

## 分片口径（内存约束）

几百万篇文档，任何一步都不许把所有文档的完整特征或所有文档对堆进内存。允许的做法包括：给每篇文档算固定长度的指纹（签名），按指纹分带分桶，把桶或签名落到临时文件再按块处理，按文档编号分块扫描等等。具体要求：

- **近似只能用来找候选**：指纹、分带、分桶都可以，但最终判定必须回到上一条的**精确 Jaccard** 上（用两篇文档的完整特征集重算）。这样结果与分块方式、分块顺序、指纹参数都无关，只与数据本身有关。
- **预算**：生产规模（几百万篇）下进程内存峰值不超过 **512 MB**；样例数据集（3000 篇）跑完不超过几分钟。
- 内存峰值要能被测出来（`tracemalloc` 之类的工具），测试里要有这一项。

## 门槛（在 samples 数据集上）

`samples/labels.csv` 是人工标注：`id_a,id_b,label`，`1` 表示这两篇是同一篇内容的变体（正例），`0` 表示确认无关（负例，包含一批「模板相近但其实无关」的）。

| 指标 | 定义 | 门槛 | 参考实现实测 |
| --- | --- | --- | --- |
| 召回 | 被判为同一组的正例对 / 正例对总数 | **≥ 0.95** | 1.00 |
| 误报 | 被判为同一组的负例对 / 负例对总数 | **= 0** | 0 |

误报是硬零：只要把一条负例对判进同一组就不算过。参考实现是「指纹找候选 + 精确 Jaccard 复核」，所以不会因为指纹碰撞引入误报。

## 分组与输出规则

- 每组用**组内编号最小**的那篇当代表。
- 输出一行一组，成员编号升序排列、逗号分隔，第一个就是代表；组与组之间按代表编号升序。
- **只输出成员数 ≥ 2 的组**，单篇文档不占行。
- 行尾 LF；同一份数据跑两遍，输出必须逐字节一样。

```text
1,2,3,4
5,6,7,8
```

## 边界情况

samples 里都构造了，实现要按下面的口径处理：

| 情况 | 期望 |
| --- | --- |
| 空文档（特征集为空） | 两篇空文档相似度为 1，会分到同一组；空文档与任何非空文档相似度为 0 |
| 只有几个字的文档（归一化后长度 < 3） | 整串作为唯一特征；完全相同的短文档会成组，只差一个字就不成组 |
| 完全一样的文档 | 相似度 1，必然成组 |
| 看起来像但其实无关（同一模板、不同主体词） | 相似度要低于阈值，不许成组——这是误报门槛里专门盯的一类 |

## 样例

```text
samples/docs.jsonl           3000 篇文档，每行 {"id":N,"text":"…"}
samples/labels.csv           标注对（id_a,id_b,label），402 条正例 + 800 条负例
samples/expected-groups.txt  τ = 0.8 下的期望分组（102 组）
```

数据集里包含 60 组「原文 + 3 篇轻改写」（含转载前缀、标点改动、尾部补充）、40 组完全重复、2 篇空文档、2 篇两字文档、6 篇模板相近的干扰文档，其余是互不相关的内容。期望分组由「精确 Jaccard + 连通分量」得到，并与构造时的真值逐组核对过。

### 候选怎么找：按文档频率排序的前缀过滤（不用 MinHash）

没有采用 MinHash 分带，而是**前缀过滤**（prefix filtering），因为它是确定性的、数学上可证不漏：

- 若 `Jaccard(A, B) ≥ τ`，则 `|A∩B| ≥ ⌈τ·max(|A|,|B|)⌉`。两边各自把特征按**同一个全局序**排序、各取前 `n - ⌈τ·n⌉ + 1` 个作为「前缀」，由容斥原理两边前缀必然共享至少一个特征。因此把每篇文档的前缀 token 放进倒排、同桶两两成对，就是完备的候选集——漏检为零，与阈值、语料都无关。
- 全局序用的是 **token 的文档频率（df）升序**（频次相同按字典序）：每篇文档只索引它「最稀有」的那部分特征。高频模板 3-gram 进不了前缀，「模板相近但无关」的文档天然不会大量成为候选。排序方式不影响完备性，只影响候选数量。
- 阈值附近的浮点误差用 `τ - 1e-9` 建索引来吸收（前缀只会更长、候选只会更多），最终判定仍用精确的 `τ`。

### 分块流式处理（内存口径）

三遍处理，任何一步都不把全量特征或全量文档对堆进内存：

1. **扫描**：文档流式读一遍，逐篇算特征。完整特征集（排序后的 token）写入临时特征文件，内存里只留 `(id, 偏移量, 特征数)` 三个紧凑 `array`（每篇 24 字节）；同时把 `(token, doc_id)` 记录和 `(doc_id, 特征数)` 记录写到临时文件。
2. **候选产生**：全部中间结果走**分块外排序**（`neardup/externalsort.py`）——内存里只排序一个块（默认 20 万行），块落临时文件后多路归并，归并路数有上限（32 路，防止打开文件过多撑爆内存）。流程：按 token 归并得到 df → 按 `(doc, df, token)` 归并 → 每篇文档截取最稀有的前 k 个 token 作为前缀记录 → 前缀记录按 token 归并、同桶两两成对 → 候选对排序去重。候选对里 doc 编号零填充，让字符串排序等价于数值排序，复核时同一篇文档的候选对聚在一起。
3. **精确复核**：流式读候选对，先用特征数做尺寸预过滤（`J ≥ τ` 要求 `min ≥ τ·max`，零成本排除），通过的对才从特征文件按偏移量读出**这两篇**的完整特征集重算精确 Jaccard（配一个有界 LRU 缓存，默认 4096 篇）。任意时刻内存里只有常数篇文档的特征。≥ τ 的边进并查集，最后取连通分量。

空文档没有特征、不进倒排；两篇空文档相似度按定义为 1，单独彼此成组。

### 内存峰值怎么测

`tests/test_neardup.py` 里 `TestMemoryBounded` 用 `tracemalloc` 实测：同一批数据分别用「小块 + 小缓存」和「默认参数」跑两遍，断言小块配置峰值 < 64 MB、默认配置峰值 < 512 MB 预算，且小块峰值显著更低（证明峰值随分块参数可控），两种参数下输出逐字节一致。实测参考：样例数据集（3000 篇）默认参数峰值约 54 MB，小块配置约 5 MB；生产规模（几百万篇）下内存占用由 `sort_chunk_lines` 与 `cache_size` 决定，与文档总量无关。

### 结果确定性与分组规则

- 分组 = 「相似度 ≥ τ」的边构成的**连通分量**（并查集）；代表 = 组内最小编号；组内升序、组间按代表升序、只输出成员数 ≥ 2 的组，行尾 LF。
- 所有排序键都是确定性的字符串/数值，候选完备性不依赖分块方式，最终判定是精确 Jaccard——因此输出只与数据有关，跑两遍、换分块参数，结果逐字节一样（有测试兜底）。

### 关于 labels.csv 的一对冲突标注

`(201, 202)` 在 labels.csv 里同时被标了 `1` 和 `0`。该对精确 Jaccard = 0.98，确为近重复，且在 `expected-groups.txt` 的同一组里，负例行系标注噪声。评测时同一对出现冲突标注**以正例为准**（见 `TestSampleDataset.test_recall_and_false_positive_gates`）；按此口径实测召回 1.00、误报 0。
